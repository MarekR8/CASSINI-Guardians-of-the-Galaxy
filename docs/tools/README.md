# Tools and data sources

The scope is civilian flood evacuation, not a live emergency system. On 2026-11-28 we checked the [12th CASSINI Participant Playbook](https://www.cassini.eu/hackathons/sites/default/files/2026-10/Participant%20Playbook_12th%20CASSINI%20Hackathon.pdf), [general toolkit](https://www.cassini.eu/hackathons/tools) and [partner toolkit](https://www.cassini.eu/hackathons/node/104). The playbook identifies CDSE (pp. 20–21), FlyPix (p. 23) and ESA APEx (p. 24) for this edition, and lists Kinéis and ATT in the technical agenda (p. 27). General toolkit pages include material from previous editions; an entry there does not establish current entitlement. The [Miro board](https://miro.com/app/board/uXjVEIhlQP4=/) remains the team's working reference.

## Integration selection and evidence

No new live provider connection or hardware was verified in this review.

## Access, licence, and temporal rules

| Source family | Access and reuse | Evidence and validity |
| --- | --- | --- |
| EMS, Sentinel, CDSE | [EMS terms](https://mapping.emergency.copernicus.eu/terms-and-conditions/) permit use of open products with attribution; restricted products require authorized access. [CDSE FAQ](https://documentation.dataspace.copernicus.eu/FAQ.html) describes product-specific terms and attribution; account/quota for processing applies. Do not upload private operation layers to cloud tools. | Preserve product/acquisition ID, acquisition time, AOI, derivation and source; old observation is not current safety evidence. Record all contributing scenes. |
| APEx/openEO | Catalogue entry for flood detection lists public service and CC BY-SA 4.0; actual execution requires account and available quota. Check the selected algorithm/version and input dataset rights. APEx visualisation is not a benchmarked safety product. | Preserve process ID/version, parameters, acquisition range, extent, output and quality caveats. A visualisation is not independently verified inundation. |
| FlyPix | Reference docs verify export format, not the team's account, quotas or redistribution rights. Confirm the applicable provider terms and owner permission before publishing an export. | Preserve image product ID, model/layer ID, detection time and review status. The operator alone may confirm segment closure. |
| GHSL and GloFAS | JRC lists GHSL CC BY 4.0. GloFAS has product-specific access and reuse rules; confirm the dataset or Open-Meteo API terms before recording. | GHSL reference year and estimation method; GloFAS issuance, forecast horizon, units and freshness. Missing/stale data remain unknown; neither is a resident count or observed passability. |
| Galileo/OSNMA/EGNOS/EWSS | Public GNSS services have service definitions and limitations. OSNMA authentication alone is not a safety-certified position; use receiver-approved evidence. EWSS is for authorized national authorities, not an ordinary broadcast API. | Record actual receiver report/fix time and mode; no inferred applied correction, authentication or receipt from merely seeing a signal. |
| IRIS², GOVSATCOM, Kinéis, ATT | Authorized organization/terminal or approved provider device/API as applicable. No credentials or service agreement verified for the team. Simulated profiles are not provider performance specifications. | Keep queue, delivery confirmation and owner command receipt distinct. Never mark disconnected writes delivered. |
| OSM and ORS | [OSM ODbL/attribution](https://www.openstreetmap.org/copyright). For ORS, consult [HeiGIT terms](https://account.heigit.org/info/tos) and the provider's account; terms page was not text-readable in this review. Do not assume redistribution of arbitrary responses is permitted. | Store graph version/coverage and response observation time; Routing still validates current closure/access evidence. |

## Preparation and missing inputs

Use [the blank team-input template](../../data/local/product.example.json) and [local data guide](../../data/local/README.md). Store actual keys, device identities, raw raster data and recordings only in ignored local files. The current default stack uses synthetic site/people evidence, local storage and graph; it requires no provider account.

Before claiming a new live integration, record the exact official contract/version, approved access and terms, provenance and output manifest, test replay and a visible demo status. Ask organizers for Kinéis device/API/acknowledgement documentation, ATT identity, and access to CDSE/FlyPix/APEx quotas. Do not substitute a synthetic response for an actual captured response in reporting.
